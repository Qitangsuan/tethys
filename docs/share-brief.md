## 1. 这是什么

一个个人项目：**从 AI 编程助手（DSH）的会话轨迹里，验证「注入 AGENTS.md 的行为规则」到底有没有用。**

链路：采集会话事件 → 判定「真失败」（剔除假阳性/噪音/用户中断/宿主故障/配置态）→ 统计验证（会话聚类 RR + Bonferroni）→ 门槛判断 → 注入规则。

核心取舍：**只从轨迹里学，不从想象里学；质量优先于速度；买观察，自己写判定。**
已经被砍掉的东西：dashboard、提案池、趋势、状态机、插件面板（观察层交给插件）。

## 3. 本轮新增的三个事实

### 3.1 结论：结果层验证在自然使用下不可达

后臂 2 会话 / 64 调用，是 3 天里仅有的真实使用（11-23 一次 52 次，11-24 一次 13 次；其余新解压会话是子代理空转或补采的历史会话）。
按 21.3 调用/天算：达 2,000 调用下限还需 ~91 天，达功效规划的 13,075 调用还需 **~610 天**。
旧判断「样本量差 3 倍」要更正为「**差约 200 倍**」。

### 3.2 「数据不够」不是新发现——它被说过三次

翻主线会话（11-09 起，315 条用户消息，1425 次工具调用）发现：

| 时间 | 谁说的 | 结论 |
|---|---|---|
| 11-12 | 用户 | 「项目依旧有价值，但数据不够，下次数据够多推进？」 |
| 11-20 | 用户 | 「**无法保证能一直处于这个强度，之前都是有灵感想做东西才会打开使用**」（当时 31 天均值 306 次/天，含 13 个零调用日） |
| 11-24 | 本轮 | 610 天 |

**关键**：A/B 方案当初就是按「306 次/天」设计的，而用户当场说过这个前提不成立。所以 A 路线一直不启动不是拖延，是知道底不稳。

### 3.3 观测器会静默失明——v1 的教训在 v2 复发

v1 时代踩过：`doctor.py` 把损坏的 JSON 静默吞成默认值仍报 OK，导致 44 轮「指标健康」全建在会说谎的自检上。
本轮发现 v2 同病三处，已修：

1. `kind-history.json` 损坏时静默当作「全部已知」→ 新失败族**永久不报**。改为按全量重报 + 显式告警（`previousHistoryOk`）。
2. `splitlines()` 把带裸换行的 `tool/result` 切成多行后**直接丢弃**（45 行，一直没吱声）。改为两级容错解析（保留原分隔符拼回 → 再把裸换行转义回 `\n`）。
3. 有 `call` 无 `result` 的调用静默不计。新增 `orphanCalls` / `badLines` / `unreadableSessions` 计数，非零即打印。

修复效果：坏行 45 → 33，捞回 2 条调用。剩余 33 行是写入时 UTF-8 被当 latin-1 的双重编码，**不猜**，如实报数。
另外修了门槛判据混用：原 `ready.py` 用一个 GO 布尔同时表达「样本够验证」和「有事可做」，后者天天为真导致天天报 GO。改为三级 `verify` / `work` / `none`，验证门槛改看后臂规模，并直接输出「还差几天」。

## 4. 作者的三条判断（请优先挑战）

- **J1**：结果层验证在自然使用下不可达，「再攒攒数据」是伪解。
- **J2**：规则能管的天花板很低——审计显示环境/工具类占真失败 67%，规则能覆盖的约 18%。
- **J3**：该把判据下沉到行为层（只验「规则被执行了吗」），并明确声明「行为改变 ≠ 失败变少」。

已知的反例强度：J3 的现成反例是规则 6——「read 前先 glob」从 2.6% 升到 8.6%（3.3 倍），但失败率没有显著下降。所以行为层判据只能证明「被遵守」，不能证明「有用」。

## 5. 三条路线

| 路线 | 做什么 | 代价 | 能得到什么 |
|---|---|---|---|
| **A 前瞻 A/B** | 每天固定跑 N 个任务，两臂（旧规则块 / 新规则块）对照 | 每臂 13,075 调用 ≈ 真金白银 + 每天固定时间 | 唯一能回答「规则有没有用」的路 |
| **B 判据下沉行为层** | 只验「规则被执行了吗」，样本需求低一个量级 | 零成本 | 能出「行为改变了」的硬结论，**不能**推出「失败变少了」 |
| **C 改投环境治理** | 填真失败的坑（Top：`exit_1_real` 80 / `edit_no_match` 42 / `web_fetch_fail` 33 / `file_read_missing` 26） | 一次性投入 | 真失败总量会降，但不能归因给规则 |
